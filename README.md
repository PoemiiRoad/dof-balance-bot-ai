# ⚖️ ДОФ Баланс — Telegram-бот

Бот принимает месячный отчёт `.xls` или `.xlsx`, сохраняет показания
конвейерных весов в SQLite и рассчитывает материальный баланс двух очередей
участка дробления.

## Что умеет бот

- показывает суточный баланс только по завершённым суткам;
- выводит первую смену текущего незавершённого дня отдельно;
- рассчитывает скользящий баланс за последние 1, 3, 5 и 7 завершённых суток;
- формирует недельную сводку через границу месяца;
- показывает месячный итог;
- проверяет технологические диапазоны и основные/дублирующие весы;
- формирует сигнал устойчивого отклонения только по трём последовательным суткам;
- рассчитывает движение склада влажного концентрата;
- по желанию передаёт подготовленные данные AI-ассистенту Anthropic.

Кнопки используют период последнего **успешно загруженного** отчёта. Свежий
снимок месяца полностью заменяет старый снимок этого месяца, поэтому удалённые
или исправленные дни не подмешиваются из предыдущего файла.

Один запущенный экземпляр бота соответствует одной общей производственной базе:
все допущенные сотрудники видят один и тот же последний отчёт. Кто выполнил
загрузку, сохраняется в журнале. Для независимых участков нужно запускать
отдельные экземпляры с разными `DB_PATH`.

## Безопасный импорт отчёта

Бот ожидает лист `ДетСменТекМесяц` и строки `Дата:` / `Смена:`. Пробелы,
неразрывные пробелы, регистр и распространённые варианты названий конвейеров
нормализуются.

При импорте:

- обязательно проверяется наличие входных весов конвейеров 3 и 4;
- нечисловые и бесконечные значения отклоняются;
- ненулевые данные за будущую дату отклоняются без изменения старой базы;
- пустые колонки текущего и будущих дней не сохраняются;
- завершённые нулевые сутки и нулевые смены сохраняются как реальные нулевые показания;
- отсутствие строки или показания не подменяется нулём: зависимый расчёт становится недоступным;
- текущий календарный день исключается из суточных расчётов, а первая смена сохраняется отдельно;
- файл с несколькими месяцами в строке дат отклоняется;
- для формулы `.xlsx` без сохранённого результата выводится понятная ошибка — такой файл нужно открыть, пересчитать и сохранить в Excel;
- запись месяца выполняется одной транзакцией: при ошибке прежние данные остаются.

Если в файле отсутствуют строки для контроля норм, дублей или склада, бот
показывает предупреждение после загрузки. Пропущенные поля не маскируются.

## Формулы баланса

```text
Баланс 1  = (102 + 34 + 24ПП + 24ХВ − 28А.I − 4) / 4 × 100%
Баланс С1 = (102 + 24ХВ + 24ПП + 32 − 28А.I − 14) / 4 × 100%
Баланс 2  = (101 + 33 − 28А.II − 3) / 3 × 100%
Баланс С2 = (101 + 31 − 28А.II − 15) / 3 × 100%
```

Порог баланса:

- до ±2% включительно — норма;
- более ±2%, но не более ±5% — предупреждение;
- более ±5% — критичное отклонение.

Нулевое показание контролируемого выходного конвейера при ненулевом входе
считается критичным. Отсутствующее показание отличается от нуля и не участвует в расчёте.

## Скользящий баланс

Бот не усредняет суточные проценты. Для каждого окна сначала складывается
абсолютный тоннаж всех участвующих конвейеров, затем к суммам применяется
формула баланса.

Текущая смена в окно не включается. Если между тремя последними записями есть
пропуск календарной даты, значения показываются справочно, но устойчивый
трёхсуточный сигнал не формируется.

Скользящий расчёт уменьшает ложные суточные отклонения из-за межсуточного
перехода материала, но сам по себе не доказывает движение через бункеры. Для
доказательства нужны посменные/почасовые показания и остатки в бункерах.

## AI-ассистент

Сборка использует `claude-agent-sdk` и `CLAUDE_CODE_OAUTH_TOKEN`, полученный через
`claude setup-token`. Отдельный `ANTHROPIC_API_KEY` для этого режима не нужен и
должен быть удалён из переменных окружения, чтобы запросы не ушли в отдельный
API-биллинг.

AI работает только при ровно одном ID в `ALLOWED_USER_IDS`. Модель задаётся
`AI_MODEL` (по умолчанию `sonnet`), таймаут одного запроса по умолчанию — 300 секунд.
`effort` установлен в `medium`. Постоянные правила передаются через `SYSTEM_PROMPT`;
контекст содержит фактические показания и детерминированные расчёты без второй
копии `AI_RULES`.

AI может ошибаться. Формулы, сохранение отчёта и алерты выполняются обычным кодом;
AI используется для объяснения данных и диагностических гипотез.

## Установка

Требуется Python 3.10 или новее.

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Скопируйте `.env.example` в `.env` и заполните параметры:

```env
BOT_TOKEN=токен_от_BotFather
CLAUDE_CODE_OAUTH_TOKEN=токен_из_claude_setup-token
AI_MODEL=sonnet
AI_TIMEOUT_SECONDS=300
BOT_TIMEZONE=Asia/Qostanay
DB_PATH=dof_balance.db
MAX_REPORT_SIZE_MB=15
MAX_XLSX_UNCOMPRESSED_MB=100
ALLOWED_USER_IDS=123456789
```

Для AI должен быть указан ровно один Telegram ID в `ALLOWED_USER_IDS`.
`CLAUDE_CODE_OAUTH_TOKEN` храните только как Secret и не добавляйте реальное
значение в `.env.example`, GitHub или сообщения.

Запуск:

```powershell
python main.py
```

## Обновление существующего бота

1. Остановите процесс бота.
2. Сделайте резервную копию `dof_balance.db`.
3. Замените файлы проекта содержимым новой версии.
4. Повторно выполните `pip install -r requirements.txt`.
5. Не удаляйте рабочий `dof_balance.db`: недостающие таблицы и столбцы создаются автоматически.
6. Запустите бот и загрузите свежий отчёт один раз.

После загрузки имя активного файла показывается в разделе суточного баланса.

## Самопроверка

```powershell
python -m unittest discover -s tests -v
python -m py_compile main.py balance_logic.py balance_monitor.py
```

Регрессионные тесты покрывают формулы, `.xls`, `.xlsx`, SQLite, скользящие окна,
AI-контекст, меню, склад и обработчики. GitHub Actions автоматически запускает
тесты и компиляцию при изменениях Python-кода. `AUDIT_REPORT.md` содержит
исторический аудит и не заменяет результат текущего CI.
